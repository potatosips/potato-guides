FreeGames

Free game announcement cog setup with GamerPowerAPI, plus the known fgset showsettings crash fix.

What this page covers: configuring GamerPowerAPI, setting the announcement channel, selecting stores, enabling posts, and fixing the TypeError: 'set' object is not subscriptable crash in showsettings.

Install

Use the repo that provides freegames. Replace CRAY_BOUNTY_REPO_URL with the actual cray-bounty-cogs repository URL you use.

oa repo add cray-bounty-cogs CRAY_BOUNTY_REPO_URL
oa cog install cray-bounty-cogs freegames
oa load freegames

GamerPowerAPI setup

Replace #free-games with your own free games announcement text channel.

oa fgset gpapi channel #free-games
oa fgset gpapi stores steam epic-games-store ubisoft gog itchio ps4 ps5 xbox-one xbox-series-xs switch android ios vr battlenet origin drm-free xbox-360
oa fgset gpapi toggle
oa fgset showsettings

Expected settings

  • GamerPowerAPI: On
  • Channel: your chosen free games text channel
  • FreeStuffAPI: Off unless you enable it
  • Stores: selected PC, console, mobile, VR, and DRM-free sources

Known showsettings crash

The setup can work correctly while oa fgset showsettings still crashes. The bug happens when the cog sends a Python set directly into cf.humanize_list().

Error in command 'freegamesset showsettings'
TypeError: 'set' object is not subscriptable

Root cause

conf.gamerpower.stores_to_check is stored as a set. Babel list formatting expects an indexable list-like object, so it fails when it tries to access items by index.

Patch

Edit the installed cog file that contains the settings display command, usually inside the RedBot venv cog install path:

nano /path/to/freegames/commands/settings.py

Change this:

cf.humanize_list(conf.gamerpower.stores_to_check)

To this:

cf.humanize_list(sorted(conf.gamerpower.stores_to_check))

Suggested fixed display line:

f"  - Stores to check: {cf.humanize_list(sorted(conf.gamerpower.stores_to_check)) or 'All of them'}

",

Reload and verify

oa reload freegames
oa fgset showsettings

Notes

  • This is not an EmbedUtils issue.
  • This is not caused by missing Discord Embed Links permission.
  • GamerPowerAPI configuration can still be valid; the crash is limited to the settings display command.
  • Unrelated logs from Birthday or YALC do not affect this issue.
